# Test exchange format (v1)

A test is one JSON file (a "Test Document"). The same format is used for import, export and the stored revisions. Authoritative design: [plan section 11](../idea/plan.md). Machine-readable schema: `schema/test.v1.schema.json` (generated by `manage.py export_schema`; never edit by hand). Ready-made files: [examples](examples/). Prompts for chat AIs: [llm/create-test.prompt.md](llm/create-test.prompt.md) (English, from a topic) and [llm/test-from-textbook.uk.prompt.md](llm/test-from-textbook.uk.prompt.md) (Ukrainian, from a PDF textbook; also on the Help page of the app).

Principles: one file, one test. Correctness is marked inline (`"correct": true`). Ids are optional on import (the app generates `q1`, `q2`, ... and `a`, `b`, ...) and always present on export. Every optional field has a default. Import is lenient (unknown fields give a warning and are ignored), export is canonical.

## Smallest valid file

```json
{
  "format": "knowledge-tester/test",
  "version": 1,
  "test": {
    "title": "Capitals",
    "questions": [
      {
        "type": "single_choice",
        "text": "What is the capital of Ukraine?",
        "options": [{ "text": "Kyiv", "correct": true }, { "text": "Lviv" }]
      }
    ]
  }
}
```

## Test level

| Field | Values | Default |
|---|---|---|
| `format` | `"knowledge-tester/test"` | required |
| `version` | `1` | required |
| `test.title` | text, 1-200 chars | required |
| `test.description` | text | `""` |
| `test.language` | `en`, `uk`, ... (max 8 chars) | `"en"` |
| `settings.time_limit_minutes` | whole number >= 1, or `null` | `null` |
| `settings.shuffle_questions`, `shuffle_options`, `one_question_per_page` | true/false | `false` |
| `settings.show_result` | `none`, `score`, `full` (score plus correct answers) | `score` |
| `settings.max_attempts` | whole number >= 1 | `1` |
| `taker_fields` | `[{key, label, required}]` | one required `name` field |
| `grading.enabled` | true/false | `true` |
| `grading.scale` | `percent`, `points`, `pass_fail`, `ua_12`, `five_point`, `custom` | `percent` |
| `grading.pass_percent` | 0-100 | `50` |
| `grading.thresholds` | `[{min_percent, label}]`, highest first; only for `custom` | none |
| `questions` | 1-200 items | required, unless `variants` is given |
| `variants` | 2-10 items, see below | none |

## Questions

Common fields: `id` (unique text, generated if missing), `type`, `text` (1-5000 chars, plain text), `points` (number >= 0 in steps of 0.5, default `1`; `0` = ungraded), `required` (default `false`), `hint`.

| `type` | Extra fields | Rule |
|---|---|---|
| `single_choice` | `options` (2-20), `penalty` (0-1, default 0) | exactly one correct option |
| `multiple_choice` | `options` (2-20), `scoring`: `partial` (default), `all_or_nothing`, `per_option` | at least one correct option; `per_option` needs a numeric `weight` on every option |
| `choose_n` | `options` (2-20), `n` | exactly `n` correct options; the taker may pick at most `n` |
| `short_answer` | `accept` (non-empty list), `mode`: `text` (default) or `numeric`, `case_sensitive` (false), `tolerance` (0), `review_unmatched` (false) | in numeric mode every `accept` entry is a number (`.` or `,` as decimal separator) |
| `open` | `rubric` | graded by the teacher |

Option: `{ "id"?, "text", "correct"? (default false), "weight"? }`. Option ids are unique within the question. Fields that do not apply to a type are ignored with a warning. `image` is reserved and ignored in v1.

Scoring rules and grade scales: plan sections 9 and 10.

## Variants

A test can have several parallel versions. Instead of `test.questions`, write `test.variants`: a list of `{ "id"?, "title"?, "questions": [...] }`. Settings, taker fields and grading are shared by all variants. Every taker gets exactly one variant; they are handed out in turn (starting from a random one), so a class is split evenly and neighbours get different questions.

```json
"test": {
  "title": "Fractions",
  "variants": [
    { "title": "Variant 1", "questions": [ { "type": "open", "text": "..." } ] },
    { "title": "Variant 2", "questions": [ { "type": "open", "text": "..." } ] }
  ]
}
```

Rules: a test has either `questions` or `variants`, never both. `title` is optional (people then see "Variant 1", "Variant 2" in their own language); variant ids are generated as `v1`, `v2`, ... Question ids are unique in the whole test, also across variants (generated ids simply keep counting). Each variant holds 1-200 questions. A file with a single variant is imported as a plain test, with a warning. Variants that are worth different numbers of points give a warning: grades use percent, so it works, but equal totals are easier to explain. Full example: [examples/variants.json](examples/variants.json).

Results show each taker's variant; question statistics are computed per variant; in the results CSV a `Variant` column is added and the question columns are numbered by position in the taker's variant.

## Validation report

Import never fails silently. Errors block the import; warnings do not. Each message has a path and says what to change:

```
ERROR  test.questions[1] (id "q2", multiple_choice): no option is marked correct. Add "correct": true to at least one option.
ERROR  test.questions[3].points: must be 0 or more, got -1.
WARN   test.settings.shuffle: unknown field, ignored. Did you mean "shuffle_options"?
```

The import page shows the same text in a "Copy for the AI" box, so it can be pasted back into a chat to get a corrected file. Invalid JSON reports the line and column. A Markdown code fence around the JSON is removed automatically (with a warning).

## Versioning

`version` is an integer. Adding optional fields does not change it. A breaking change bumps it and the importer keeps reading older versions.
